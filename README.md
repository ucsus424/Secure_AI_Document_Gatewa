# Secure AI Document Gateway

Локальное Python-приложение для поиска чувствительных данных в документах, их замены на токены и последующего восстановления. Анализ выполняется локально через Ollama и Gemma; внешние AI API не используются.

Убранные значения сохраняются в локальной базе SQLite `data/gateway.db`. Пользователь получает только SAFE-файл, например `отчёт_SAFE_39F3C1EE.docx`. Для восстановления загрузите этот файл (или ответ AI): программа найдёт документ по его номеру, а если номера нет — предложит выбрать документ из базы.

## 1. Что нужно

- Windows, macOS или Linux.
- Python 3.9 или новее и пакет `lxml`: `python -m pip install lxml` (нужен для работы с DOCX без повреждения разметки Word).
- Ollama 0.30.5 или новее.
- Около 8 ГБ свободного места для модели `gemma4:12b-it-qat` и достаточно оперативной памяти для её запуска.

Распакуйте ZIP в отдельную папку. В пути могут быть пробелы и русские буквы. Все команды ниже нужно выполнять из корневой папки проекта, где лежит `app.py`.

## 2. Установка Python, Ollama и Gemma

1. Установите Python с [python.org](https://www.python.org/downloads/) и проверьте:

   ```bash
   python3 --version
   ```

   На Windows команда обычно выглядит как `py --version` или `python --version`. При установке включите **Add Python to PATH**.

2. Установите Ollama с [ollama.com/download](https://ollama.com/download). На macOS и Windows запустите установленное приложение. Для Linux можно использовать команду со страницы загрузки. Проверка:

   ```bash
   ollama --version
   ```

3. Скачайте модель:

   ```bash
   ollama pull gemma4:12b-it-qat
   ollama list
   ```

Обычно Ollama запускает локальный сервис автоматически. Если приложение не видит модель, запустите в отдельном окне терминала `ollama serve` и оставьте его работать.

## 3. Запуск веб-интерфейса

macOS/Linux:

```bash
cd "/пут/к/Secure_AI_Document_Gateway"
python3 app.py ui --port 8765
```

Windows PowerShell:

```powershell
cd "C:\пут\к\Secure_AI_Document_Gateway"
py app.py ui --port 8765
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Остановка сервера: `Ctrl+C` в терминале. Веб-сервер слушает только `127.0.0.1` и не открывается в локальную сеть.

Порядок работы:

1. В блоке **Создать безопасную копию** загрузите TXT или DOCX. Скачается только SAFE-файл; убранные значения сохранятся в базе.
2. Внешней AI-системе передавайте только SAFE-файл.
3. Для восстановления загрузите SAFE-файл или ответ AI (TXT или DOCX).

Как программа выбирает документ для восстановления. Автоматически — **только по номеру документа**: метки вида `⟦PERSON_001⟧` повторяются почти в каждом документе и могут означать разных людей.

1. **Номер выбран пользователем** (кнопка выбора в интерфейсе или номер в CLI) — используется только он. Если такого номера нет в базе, будет ошибка; другой документ не подбирается.
2. **Номер в самом файле:** свойство внутри DOCX (`SecureGatewayDocumentId`, сохраняется при переименовании) и `_SAFE_XXXXXXXX` в имени файла.
   - Номера совпадают или есть только один — восстановление.
   - Номера разные — сообщение о несоответствии и выбор одного из двух документов.
   - Номер есть, но документа нет в базе — ошибка, подбора по меткам нет.
3. **Номера нет нигде** (файл переименован, ответ AI в TXT) — программа показывает документы, которым принадлежат все метки файла, и просит выбрать нужный. Даже если подходит один документ. У каждого варианта указано, сколько его меток нет в файле — это подсказка, а не решение.

Проверки при восстановлении:

- в файле есть метка, которой нет в выбранном документе — ошибка «файл не относится к документу», итоговый файл не создаётся;
- меток документа нет в файле (например, абзац удалили при редактировании) — восстановление выполняется, но программа предупреждает, каких меток не хватает.

Поддерживаются только TXT и DOCX. XLSX и PPTX не принимаются.

Защита от «утечек» в SAFE-файле:

- значение находится, даже если в документе оно разбито на несколько строк-абзацев или записано с неразрывными пробелами;
- если значение занимает несколько соседних абзацев, метка ставится в первый абзац, а остальные строки значения стираются (абзацы остаются пустыми). После восстановления полное значение окажется в одной строке;
- после создания SAFE-файла программа проверяет, что ни одно найденное значение в нём не осталось (без учёта пробелов и переносов). Если осталось — SAFE-файл не выдаётся и в базу ничего не записывается, а пользователь видит, какие метки не удалось заменить. Так бывает, например, когда значение разнесено по разным ячейкам таблицы.

## Запуск на сервере (сетевой режим)

По умолчанию интерфейс доступен только на этом компьютере (`127.0.0.1`). Чтобы им пользовались с других компьютеров сети, запустите программу на сервере в сетевом режиме.

1. Установите на сервер Python, `lxml`, Ollama и модель так же, как в разделах 1–2. Ollama остаётся на сервере по адресу `127.0.0.1:11434`, в сеть её открывать не нужно.
2. Один раз откройте порт в брандмауэре: правой кнопкой по `open_firewall_port.cmd` → **Запуск от имени администратора**.
3. Запустите двойным щелчком `start_server.cmd`. В окне появятся адреса, например `http://192.168.1.25:8765`. Окно не закрывайте, пока сервер нужен.
4. На другом компьютере откройте этот адрес в браузере.

То же из командной строки:

```powershell
python app.py ui --host 0.0.0.0 --port 8765
```

`--host 0.0.0.0` — принимать подключения со всех сетевых адресов сервера; можно указать и конкретный IP сервера. В сетевом режиме на странице показывается значок «Сетевой режим».

Ограничения текущей версии: нет входа и разграничения доступа (любой в сети видит и восстанавливает любые документы), нет шифрования и HTTPS, сервер рассчитан на одного пользователя одновременно, после перезагрузки сервер нужно запустить вручную. Используйте сетевой режим только с тестовыми документами.

Если с другого компьютера не открывается: проверьте, что сервер запущен, порт открыт в брандмауэре, а компьютеры находятся в одной сети.

## База данных

- Файл: `data/gateway.db`. Папка и таблицы создаются автоматически при первом запуске. Другой путь можно указать параметром `--db`.
- Таблица `documents`: номер документа, имя исходного файла, дата создания.
- Таблица `entities`: номер документа, токен (`PERSON_001`) и исходное значение.
- **База содержит исходные чувствительные данные в открытом виде.** Не отправляйте её во внешние системы и не храните в папке, которая синхронизируется с облаком.
- Посмотреть содержимое можно, например, программой DB Browser for SQLite.

## 4. Промпт и настройки

Основной промпт лежит в `prompts/dlp_system_prompt.txt`. После его изменения перезапустите Python-сервер. Другой файл промпта можно указать без изменения кода:

```bash
python3 app.py ui --prompt prompts/my_prompt.txt --port 8765
```

Модель и адрес Ollama тоже можно переопределить:

```bash
python3 app.py ui --model gemma4:12b-it-qat --ollama-url http://localhost:11434
```

Дефолты находятся в `core/detector.py`. Логика замены — в `core/anonymizer.py`, работа с DOCX — в `core/office.py`, база данных — в `core/database.py`, выбор документа при восстановлении — в `core/document_lookup.py`, веб-интерфейс — в `web_ui.py`.

## 5. CLI и тесты

Приложение можно запускать без UI:

```bash
python3 app.py scan document.docx
python3 app.py anonymize document.docx --output-dir result
#   SAFE document: result/document_SAFE_39F3C1EE.docx
#   Document ID: 39F3C1EE
python3 app.py restore document_SAFE_39F3C1EE.docx   # номер есть в файле
python3 app.py restore answer.txt 39F3C1EE           # номера в файле нет: программа покажет список, укажите номер
python3 app.py --help
```

Проверка кода после изменений:

```bash
python3 -m unittest discover -s tests
```

Для DOCX-тестов нужен `python-docx` (`pip install python-docx`); без него эти тесты пропускаются. Тесты не отправляют данные во внешнюю сеть и используют временную базу, а не `data/gateway.db`. История решений и текущее состояние проекта описаны в `PROJECT_CONTEXT.md`.
